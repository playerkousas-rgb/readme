# Pre-mortem 模板 — 未開工先假設佢死咗（可選）

> 來源：MiroFish 嗰類「AI 人格鬧你個 idea」嘅平價版（判決見真理倉 docs/38 §4、docs/40 §2.3）。呢份唔使起模擬引擎、唔使燒成千個 agent 嘅 token：一次 AI 對話，扮幾個人鬧一次就夠。
> **紅線先講**：產出永遠係**待驗證假設**，唔係用戶證據。唔好將 AI 人格講嘅嘢寫入「用戶想要」嗰欄；真正嗰關永遠係問真人（INTAKE 第 0 步）。

## 幾時用

- 新 app idea 仲係一兩句講完，未寫任何 code 之前。
- 你覺得個 idea「太順」、冇人鬧過佢嗰陣。
- 唔啱用：已經有真人用家鬧緊你嗰陣（聽真人先）；唔好用嚟代替問卷或者試用。

## Prompt（成段 copy，填方括號）

```text
我哋諗住做一個產品：[一句講晒係乜產品、畀邊個用、解決咩問題]。
假設而家係一年後，呢個產品已經失敗收皮。
請你分飾下面四個人，每人用佢嘅身分講：佢嗰陣點解會咁諗、邊件事令佢放棄／唔用。
唔好客氣，唔好讚好，專講會令佢死嘅原因；唔知嘅嘢就講「要問真人先知」，唔好作。

1. [目標用戶] 本人（第一次用，冇耐性）
2. 要畀錢／批預算嗰個人（睇成本同回報）
3. 日日要用佢做嘢嘅前線人員（睇麻唔麻煩）
4. 競爭對手嘅用戶（已經有代替品，冇理由轉）

最後輸出一個表：每行一個死因，寫明 [邊個人講]、[死因]、[點樣用真人驗證佢係咪真]、[如果係真，開工前要改乜]。
表以外唔好加結論，唔好講「個 idea 好唔好」。
```

## 點收貨

1. 將輸出個表貼入呢個 repo 嘅 `docs/`（或者 SCOPE.md 尾段），標題寫「Pre-mortem 假設（未驗證）」。
2. 逐行決定：邊啲要拎去問真人（寫入 INTAKE 問題清單）、邊啲開工前已經改到、邊啲接受風險。
3. 真人答完之後，喺原表加一欄「真人結果」，唔好刪 AI 原稿——留住先睇到邊啲係 AI 偏見、邊啲係真問題。
4. 如果四個人格鬧嘅嘢全部同你原本諗法一樣，一個新觀點都冇，唔好當「驗證通過」，嗰個只係代表個 prompt 太窄，換問題再問或者直接去問真人。
