## 0. 一句定位

> **一個入口、一套規格；中央平台身份＋區／旅自管帳戶並存：童軍生態嘅平台＋工具。**

- **一個入口**：APP STORE（唯一）。
- **中央身份**：適用於接入 `PLAT-02` 嘅 App，由 APP STORE／ADMIN 開戶、冇自助註冊；`CEN-01` 區系統同 `TRP-01` 旅系統例外，使用區／旅自管後端及帳戶。
- **一套規格**：每個 App 都用同一份規劃書（[02-APP-SPEC](02-APP-SPEC.md)）＋同一套分類代號，Agent 讀得明、你我對得上。

## 1. 八層分類（2.0 定稿）

| 層 | 名稱 | 入面有乜 | 邊個用得 | 邊個可改 |
|:--:|---|---|---|---|
| **L0** | **平台層（4 件）** | ① APP STORE 殼 ② 身份核心 ③ ADMIN ④ 通告中心 | 全部人（登入）／ADMIN 只有你 | 只有你 |
| **L1** | **中央生態圈** | 區系統、服務平台（成員）、管理系統、訓練班系統、專章秘書系統 | 區／旅職員、相關領袖 | 各系統負責人 |
| **L2** | **旅團生態圈** | 旅系統、支部 portal ×5、BADGE／進度 ×4、BOOK ×4 | 旅／支部領袖＋成員 | 旅／支部領袖（按授權單位；旅系統自管後端） |
| **L3** | **工具 App** | 圖鑑、地圖、繩結、摩斯、定向、遊戲、相片、簡報、**集會類**… | 領袖／成員（權限有小差異） | 你 |
| **L4** | **內容與素材** | 圖卡／PPT／連結、投稿、素材庫 | 公眾睇（如開放） | 你 |
| **L5** | **基礎設施** | API 代理、轉駁器（短連結）、備份、監控、測試環境、成本 | — | 你 |
| **L6** | **AI** | GEMINI（統合輔助平台） | 你／領袖（**假設會漏，見 §5**） | 你 |
| **L7** | **治理** | 真理倉規則、App 規格、版號、審計、私隱 | Agent／你 | 你 |

**分類三鐵律**：
1. **一個 App 只屬一層**（唔准「又 portal 又 App」）。
2. **L0 永遠只有 4 件**；多一件就代表有嘢未想清楚。
3. **資料權限由資料所屬系統後端負責**；唔可以直接寫對方 DB。Central Apps 可接 `PLAT-02`；`CEN-01`／`TRP-01` 自管後端／身份。跨系統交換要經明確 API／授權並由後端驗證。

## 3. 小童軍（`gh`）：唔係「少一個系統」，係另一種進度

你講：小童軍按**進團年資**每年一隻（徽章），所以冇進度追蹤。

**2.0 做法**：小童軍**唔需要**進度 App／BOOK／徽章 App；佢要嘅係「**年資記錄**」：

- 資料：`joined_at`（入團日）＋每年自動計「第 N 年」＋你（或支部領袖）標「已頒發」。
- 放邊：**支部 portal 內一頁**（唔另開 App），因為只需要 3 個欄位。
- 好處：唔會為咗一個 badge 開第 5 個系統；亦唔會扮佢有進度系統。

| 支部 | portal | 集會（L3） | 年資記錄 | 徽章 | 進度 | BOOK |
|---|:--:|:--:|:--:|:--:|:--:|:--:|
| 小童軍 `gh` | ✅ | ✅ | ✅（portal 內） | — | — | — |
| 幼童軍 `cubs` | ✅ | ✅ | — | ✅ | ✅ | ✅ |
| 童軍 `scout` | ✅ | ✅ | — | ✅ | ✅ | ✅ |

## 4. 唔買網域 → 三個必然後果（要接受，唔好當 bug）

| 後果 | 現實 | 我哋嘅做法 |
|---|---|---|
| **cookie 唔可以共用** | `*.vercel.app` 屬 PSL，每個 App 係獨立 site | **60 秒一次性票**：中心簽 → App 驗 → App 自己種 cookie（[docs/61](../docs/61-registration-gate-and-single-session.md) §2） |
| **PWA 要逐個裝** | 每個 App 一個 icon、一個 SW | APP STORE 殼都可以裝（做「總入口」icon），但子 App 想離線就仍要各自裝 |
| **「唯一入口」只能做到軟閘** | 直打子站網址可以繞（純靜態 App） | 有後端嘅加硬驗票；靜態 App 認命做軟閘（[docs/61](../docs/61-registration-gate-and-single-session.md) §6 MG7：**唔可以用 standalone 放行**） |

**中央身份 App**：用戶登入一次，經 60 秒票換取各 App 自己嘅 session（通常 8 小時）。`CEN-01`／`TRP-01` 使用本地帳戶時，登入／session 由各自後端管理，同一帳戶可多裝置登入；唔承諾中央 SSO。

## 5. GEMINI（L6）：當「會漏」嚟設計

你講：**係 Canvas 類，A 登入開到，就可以分享俾未登入嘅 B**。

**結論（寫死，免得日後有人以為加咗閘就安全）**：

1. GEMINI **唔係入口**，只係 L6 工具；APP STORE 唔會靠佢做任何把關。
2. **唔可以**放任何「只有某啲人應該睇到」嘅資料（名單、成績、個人資料、收費）。要放，就當「已公開」。
3. 可以加「登入先開得」嘅門面（減少路人），但**唔可以**當成保護；文檔要寫明「可被分享繞過」。
4. 如果日後真要有保護嘅 AI 功能 → 要**重寫成有後端嘅 App**（API key 喺 server、資料喺 DB、每次請求驗票），唔可以靠單檔 HTML。

## 7. 一次上架＋用戶自訂版面（本次新增需求）

你講：**2.0 唔逐個推，全部直接上架，讓用戶自訂自己嘅 APP STORE 擺位／分類／要唔要。**

### 7.1 資料模型（新表）

```sql
create table public.user_app_prefs (
  member_id uuid not null references public.members(id) on delete cascade,
  app_slug  text not null,
  visible   boolean not null default true,   -- 唔要就隱藏（唔等於冇權限）
  pinned    boolean not null default false,  -- 釘去「我的最愛」
  grp       text,                            -- 用戶自訂分類（我自己叫「常用」「訓練」）
  sort      int  not null default 0,
  updated_at timestamptz not null default now(),
  primary key (member_id, app_slug)
);
```

- **中央用戶預設版面**由「角色 × 單位」決定（例：幼童軍領袖預設見到 cubs 全套 + 工具）。`CEN-01`／`TRP-01` local account 不依賴中央 `members`／`scopes`；由 APP STORE 公開非敏感入口，再由本地後端驗證。
- 用戶改嘅只係**自己嗰份**，唔影響其他人。
- **隱藏 ≠ 冇權限**：冇權限嘅 App 根本唔應該出現喺目錄（由 `scopes` 過濾），用戶只可以喺「有權限」之中揀要唔要。

### 7.2 用「可見性」做灰度（解決「一次上架」嘅風險）

你唔想逐個推，但又唔想一次過爆：

1. 新 App 上架時，`apps.visible = true` 但**只喺你嘅預設版面見到**（其他用戶未加）。
2. 你試完 → 開放畀某一組（例：一個旅）→ 再全面開放。
3. 出事 → 中央 App 由 `apps.status='paused'`／`access_mode='closed'` 停用；`CEN-01`／`TRP-01` 只可由 APP STORE 隱藏入口，後端停用由區／旅系統管理者負責。

> 即係：**「一次上架」係對外一次過；內部灰度靠「預設版面 + 可見性」**，唔使改 App 代碼。

### 7.3 上架前必須有嘅三樣（否則「一次上架」＝一次死晒）

- **回滾**：Vercel 每個專案可 promote 舊 deployment；你要識 30 秒內回到上一版。
- **分組測試**：至少 1 個旅 + 1 個支部做 pilot（唔係你自己一個人試）。
- **中央 App 停用開關**：`apps.access_mode='closed'` 可關閉中央入口（[docs/62](../docs/62-one-control-plane-for-all-apps.md)）；`CEN-01`／`TRP-01` 私隱資料後端另由區／旅管理者停用，APP STORE 關入口唔等於後端安全閘。
